# EstateIQ

AI-Powered Real Estate Intelligence for public DarGlobal and Wasalt information.

**Live application:** [https://estateiq-pjt8.onrender.com](https://estateiq-pjt8.onrender.com)

EstateIQ answers questions from an indexed snapshot of [DarGlobal](https://darglobal.co.uk/) and [Wasalt](https://wasalt.sa/en). DarGlobal records are developer projects, company pages, and press. Wasalt records are marketplace listings. The assistant does not invent prices, availability, or project details. When the index has no relevant record, it says:

> I couldn't find verified information about this in the currently indexed DarGlobal and Wasalt data.

Every grounded answer includes the original page. Property and project cards are built from the retrieved records, not from text generated by the model.

## How it works

```text
Public pages → SQLite records → chunks → MiniLM embeddings → vector index
Question → SQL filters and vector search → OpenRouter → cited answer
```

- FastAPI serves the interface and the API. The OpenRouter key stays on the server.
- React, TypeScript, and Vite provide the chat interface.
- SQLite holds the records. Semantic search uses `all-MiniLM-L6-v2` and an inner-product index.
- Price, bedroom, city, and source questions are answered from the database. Open questions use the vector index.
- The public service does not crawl on demand. The indexed snapshot is part of the deployment.

## Indexed snapshot

| Source | What is indexed |
| --- | --- |
| Wasalt | Up to 500 public marketplace listings across the selected cities, property types, and sale or rent pages. Contact fields are not stored. |
| DarGlobal | Public project, company, and recent press pages. Unit prices are stored only when the page publishes one. |

Prices are the figures published at scrape time. They are not a live offer.

## Stack

Python 3.12, FastAPI, Pydantic, SQLite, Sentence Transformers embeddings, OpenRouter, React, TypeScript, Vite, Tailwind CSS, Docker.

## Deployment

The public application runs on Render from the Docker image in this repository. The database and search index are baked into that image. `SCRAPER_ENABLED` is false, and the API key is stored in the host environment, not in the repository.

On the free Render plan the service sleeps after about 15 minutes without traffic. The first question after sleep takes longer while the service starts.

## API

| Method | Path | Notes |
| --- | --- | --- |
| GET | `/api/health` | Database, index, and model status |
| GET | `/api/stats` | Record counts and the last scrape |
| GET | `/api/sources` | DarGlobal and Wasalt counts |
| GET | `/api/properties` | Structured listing filters |
| GET | `/api/projects` | DarGlobal developments |
| POST | `/api/chat` | `{ "message", "session_id", "source_filter" }` |
| GET | `/api/chat/history` | Sessions, or messages when `session_id` is set |
| DELETE | `/api/chat/history/{session_id}` | Deletes one conversation |
| GET | `/api/scrape/status` | Latest scrape report |
| POST | `/api/scrape/run` | Requires `X-Admin-Token` |
| POST | `/api/index/rebuild` | Requires `X-Admin-Token` |

## Tests

Backend tests use saved page fixtures. They do not call OpenRouter or the live websites.

```bash
cd backend
python -m pytest -q
```

## Limits

- The Wasalt sample is capped. It is not the full marketplace catalogue.
- DarGlobal development pages usually do not publish a unit price, so that field stays empty.
- OpenRouter free models are rate limited. When a model is unavailable, EstateIQ still shows the retrieved records and says that narrative generation is unavailable.
- Wasalt's published content terms allow use of public listing information with attribution. EstateIQ links each card back to the original page and does not collect contact details.
